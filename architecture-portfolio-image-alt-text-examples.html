How to write alt text for architecture portfolio images.

Examples for architects: clear alternatives for exteriors, interiors, floor plans and galleries, plus a usable publication checklist.

By Michal Kašpárek · Architect and visualisation specialist24 November 2026
In this guidePurpose of alt text Alt text examples Informative and decorative images Portfolio galleries Plans and diagrams Filenames and captions CMS publishing Multilingual alt text Final QA checklist

Describe the architecture, not a list of search keywords.

An architecture portfolio often contains excellent images with alt text such as “project 01”, “modern design” or a long list of services and cities. That does little for someone who cannot see the image. Alternative text gives a brief account of the information an image contributes to its page. The most useful sentence is often the answer to a simple question: what would a reader miss if this picture did not load?

For a streetscape image, mention the entrance, visible material or relationship to neighbouring buildings. For an interior, explain the spatial connection or detail the photo was selected to show. A confident description does not need to invent sustainability credentials, a location, a completion date or an award.

Google Search Central recommends descriptive alt text, meaningful filenames and helpful nearby content. Alt text can contribute to image understanding and accessibility, but it is not a guarantee of higher rankings. Describe the approved image first and resist keyword stuffing.

Notice that the useful versions describe an observable composition or architectural relationship. They do not automatically use the words “best architect”, “award winning” or the name of a city. Some images need only a short phrase. If a caption already contains the project name, photographer and date, do not make the alt attribute repeat all those facts for no reason.

Meaningful, decorative and linked images need different treatment.

Not every picture needs a full alternative description. The W3C WAI image decision tree distinguishes informative, decorative and functional images. A background texture added only for atmosphere can correctly use an empty alt attribute: alt="". This signals intentional decoration; omitting the attribute altogether is not the same thing.

A photograph that communicates the architecture usually needs a description. For an image-only link or button, the accessible name should tell the user where the link goes or what it does. “View Courtyard House project” is better than “thumbnail” if no visible text labels the destination. But if a project card contains both an image and a visible title inside one link, repeating that same title in the image alt may make the link needlessly verbose.

Review the accessible name of the entire card, not only the image file. The role of an image can also change from a purely visual decoration on the homepage to an informative illustration on its project detail page.

Give each portfolio gallery view its own purpose.

A project gallery may include a street elevation, courtyard, kitchen, staircase and material detail. Copying “Courtyard House” into every alt field makes the series hard to understand. Describe the difference: “Street-facing brick elevation with recessed entrance”, “Terrace overlooking a planted courtyard”, and “Open-tread stair beside a concrete wall”. Do not describe invisible rooms or views simply because they appear in the architectural model.

For a clickable project card with a visible heading inside the same link, the thumbnail may use empty alt if the title already clearly identifies the destination. When the linked image is the only label, the alternative should communicate the project or destination. The markup and wording need to be tested together. A gallery's keyboard navigation, previous and next buttons and close control must also have usable names; alt text does not fix an inaccessible lightbox.

Separately review mobile crops. If a detail was cropped away, its description may be wrong on the mobile variant. The portfolio image optimisation guide covers responsive variants, file sizes and loading priorities.

Plans, sections and diagrams need explanations outside their alt field.

A floor plan can contain room labels, dimensions, accessibility routes and orientation. One short alt cannot reasonably communicate the entire drawing. Start with the image's general purpose, such as “Ground-floor plan showing living spaces around a central courtyard”. Then explain the important information in adjacent HTML text, a table or another accessible representation.

A short paragraph could describe how the entrance hall connects to the kitchen and living area, and how bedrooms face the quieter wing. Only include those facts when the actual plan confirms them. A PDF download can supplement the page, but a scan-only PDF is not automatically an accessible substitute for information that exists only as tiny lettering.

The W3C guidance for complex images recommends combining a short text alternative with a longer equivalent where necessary. For downloadable drawings and presentations, see the architecture portfolio PDF accessibility checklist.

Separate alt text, filenames, captions and credits.

Each field has a different job. The filename can give a weak clue about the image subject, so courtyard-house-brick-entrance.webp is clearer than DSC_2937-final2.webp. A caption can name the project, view, year, status and collaborators. A credit helps meet publishing obligations. Alternative text describes the meaningful image content or the function of a linked picture.

Do not rename already-public image URLs casually: a CMS, CDN, social share or search result may still refer to them. Where files must move, update site references and consider redirects. Do not use alt text as a replacement for a photographer credit or invent permission to publish a rendering.

A useful pair might be alt: “Shared courtyard between brick apartment wings”; caption: “Courtyard concept, proposed project, image credit subject to approval.” That is only an illustrative pair. The project attribution and approval guide covers the publication workflow. Relevant headings and the nearby project story provide more context than trying to force everything into one image attribute.

Make image descriptions maintainable in your CMS.

A good portfolio content system stores an asset identifier, project relationship, image role, description, caption, credit and review status. Where possible, allow editors to override the alt text for a particular placement instead of forcing one default asset description everywhere. The same photograph can serve as a decorative index-card thumbnail and an informative hero inside a project case study.

Fictional content record
asset: courtyard-west-02 role: informative project gallery language: en alt: West-facing terrace with timber privacy screens caption: Courtyard House — proposed scheme credit: [check publication rights and approved credit] reviewed_by: [studio editor] revision: [project issue]

These values are examples, not real project data or evidence of publication permission.

Editors need to see the actual image and crop beside the text input. An automated description copied from an unverified prompt, internal filename or AI vision result can misstate the visible material, camera view or project status. The portfolio CMS guide

Translate the image meaning when the portfolio changes language.

A German project page should normally provide German image alternatives; a Czech project page should use Czech. Do not change the navigation language while leaving every alt description in English simply because the CMS stores one default. Read the translation in the context of the surrounding project story, especially for specialist terms such as courtyard access, façade systems or shared circulation.

Translation is not an opportunity to add cities or services unrelated to the image. An unlocated conceptual image should not suddenly claim to show a built residential project in Berlin or Prague for SEO purposes. Keep project names, materials, approvals and construction status consistent across language versions. Use the multilingual architecture portfolio QA checklist to review page language, headings, links and media together.

When a new crop is approved, verify the translated alt fields too. A mobile crop may no longer show the same terrace, stairs or background described in the original wide image. Translation QA and image QA are connected.

A practical image-alt checklist before launch.

  • Every informative image conveys its visible architectural content.
  • Purely decorative images use alt="" rather than keyword filler.
  • Image-only links and gallery controls have meaningful accessible names.
  • Repeated project views have genuinely distinct descriptions.
  • Complex plans and diagrams have a readable explanation near the drawing.
  • Alt text does not invent a city, material, completed status, view or award.
  • Captions and photographer credits are reviewed separately.
  • File renaming does not break published URLs, CMS records or image delivery.
  • Translations are appropriate for the language of each project page.
  • Editors can review and update descriptions after a crop or design revision.
  • At least one representative gallery has been tested with images unavailable and assistive technology.

Image descriptions are one part of a credible architecture website, not a substitute for project facts or thoughtful navigation. If the portfolio still lacks coherent project pages, use the architecture case-study page template before spending hours polishing the metadata of disconnected images.
