How much does an architecture studio website cost?

The useful question is what the fee includes. Compare a focused portfolio, a full practice website and a developer launch by content, editing, visualisation, ownership and long-term work.

By Michal Kašpárek, architect and founder of Atmosferi22 November 2026

Price the job the website needs to do

Asking “How much does an architecture website cost?” without defining its job is rather like pricing a building from its front elevation. A five-project portfolio, a multilingual practice website and an apartment sales platform have very different information, editing and integration needs.

Start with the intended audience, the primary enquiry, the number of genuinely distinct page types and who will maintain the content. Price the whole workflow from first project inventory to launch and handover, not merely a homepage mock-up. For a service overview, see website design for architects.

Count page templates, not just URLs

Ten projects do not necessarily mean ten individually designed websites. If all projects use one adaptable content model, the work is different from designing ten bespoke layouts. Identify which page types actually require different structure: homepage, project detail, project index, studio profile, team, services, journal and contact.

Then ask what must change between projects: gallery layout, drawing download, metadata, location, collaborators, built/unbuilt status or embedded film. The architecture project case study template helps define a repeatable project page before a CMS is chosen.

Budget for selecting and preparing the work

Content often determines the launch schedule. Project photography may exist in several sizes and crops; plans may need simplified web versions; credits and publication permissions may still be unresolved. Translating vague notes into accurate project stories also takes editorial time.

Define whether the fee includes image selection, crop review, writing, translation, captions, diagrams and migration from the old site. If the architect supplies everything publish-ready, say so. If the designer is expected to organise years of material, include that in scope. Use the project preparation checklist to expose missing inputs before pricing.

Choose an editing model that fits the studio

A CMS is not a line item with a single universal price. A small portfolio may need only an easy way to add projects and replace images. A larger practice may need multiple editors, reusable project attributes, draft approvals and role-based access. A development website may need to synchronise unit availability from another system.

Ask for a demonstrated editing workflow, not only the name of a platform. Decide who can change what, what training is included, how content is exported and who pays any recurring software licence. The architecture portfolio CMS guide compares these choices without assuming one system is right for everyone.

Understand the real cost of multilingual content

Two languages are not just two buttons in the header. Project descriptions, service pages, navigation, contact details, SEO titles and future updates need a workable translation and review process. The number of translated pages is less important than their complexity and how often they change.

Set a source language and responsible reviewer. Decide whether every project needs translation, and what happens when a new project is published. Separate professional translation and language-specific editorial work from the technical capability to store two languages. For a launch review, see the multilingual architecture website checklist.

Keep visualisation and interactive features distinct

High-resolution architectural images, a short walkthrough film, a 360-degree tour and a live 3D scene serve different purposes and carry different production and performance demands. A developer apartment selector also needs reliable data, not just an attractive animation.

Specify the intended visual deliverables, who owns the 3D model, the revision scope and the formats required for web and marketing. Atmosferi's published pricing lists architectural stills from €400 each, with some visualisation bundled into larger website engagements; check the current quote builder rather than assuming an image price covers modelling or unlimited changes.

Include the old website in the quotation

A redesign is not complete when the new homepage loads. Existing project URLs may have been shared in press articles, emails and search results. Copying only the newest work can discard useful history and break incoming links.

Scope an inventory of existing URLs, the pages to retain or retire, permanent redirects where appropriate, canonical URLs, transferred image credits and post-launch checks. If the current site has little useful content, this can be simple; if it has a large archive, it becomes a substantial part of the project. Review the portfolio URL migration checklist.

Separate launch fees from ongoing costs

Ask which costs are one-off and which recur. Common categories include domain renewal, hosting, CMS or third-party licences, backups, security and dependency maintenance, ongoing editing, translation and optional support. Some providers bundle these; others invoice them separately.

For each recurring service, ask what happens if the practice stops paying: does the website remain accessible, can the content be exported and can a different developer take over? Define support response times only when offered as an actual service. A lower initial quote can be the wrong comparison if essential ownership and maintenance are excluded.

Request a simple written comparison before choosing. Prices are meaningful only when the delivery assumptions match.

Fictional example: a six-project practice

Fictional illustrative example, not an Atmosferi commission or a real customer outcome. Consider a hypothetical two-person practice with six completed and unbuilt projects, two services, one language and an outdated site. The office wants to publish new projects itself and retain the useful links from the old portfolio.

The project brief asks for a homepage, reusable project detail template, project index, studio page, services and contact, plus a light CMS, content upload and a redirect map. The most expensive uncertainty is not the number six; it is whether the project material is actually ready and whether rebuilding old pages requires substantial editorial work. The practice requests a fixed quote against those assumptions, with optional translation and new visualisations priced separately. No conversion uplift or project price is invented for this example.

Leave the first meeting with a quotable brief

Prepare a shortlist of projects, the current website URL, one sentence about the audience, required languages, whether the team needs self-editing and any must-have integrations. Note the launch deadline and the person who can approve decisions. Ask the provider to distinguish essential scope from optional improvements.
